# 版本说明（VERSIONING）

本文说明 AMIG 各版本分支的定位、差异与适用场景。分支管理流程见 [BRANCHING.md](BRANCHING.md)，维护与支持策略见 [MAINTENANCE.md](MAINTENANCE.md)。

## 1. 当前版本线

| 版本线 | 分支 | 数据库 | 定位 | 状态 |
|---|---|---|---|---|
| **1.2.5** | `main` | SQLite 或 MySQL 8.0+（`DB_TYPE` 选择） | 合并版主维护版本 | 活跃维护 |
| 1.2.0 | `main` 历史提交 | MySQL 8.0+ | 已并入 1.2.5 | 不再单独维护 |
| **1.1.x** | `1.1.x` | SQLite（单文件，WAL） | 老数据库兼容线，仅修复，不新增功能 | 有限维护（仅兼容/安全修复） |
| 1.0.x | 无独立分支 | SQLite | 历史版本，已停止维护 | 停止维护（EOL） |

> **1.2.5 起合并两条项目线**：同一份代码通过 `DB_TYPE=sqlite|mysql` 同时支持两种后端，不再需要为老数据库单独维护分支。
> 1.1.x 老站点升级到 1.2.5 **无需安装脚本、无需迁移数据**：`DB_TYPE` 缺失时默认 sqlite，直接启动即自动补齐表结构并保留原数据。
> 需要换库时登录后台「站点设置 → 切换数据库」（三次确认、自动备份、逐表校验）。

## 2. 1.2.5 双后端能力对照

| 维度 | SQLite（`DB_TYPE=sqlite`） | MySQL（`DB_TYPE=mysql`） |
|---|---|---|
| 部署 | 单文件 `data/app.db`，零依赖 | MySQL 8.0 / 8.4 LTS，InnoDB + utf8mb4 |
| 驱动 | 标准库 `sqlite3` | PyMySQL（`cryptography` 支持 caching_sha2_password） |
| 连接管理 | 线程本地连接、WAL、`BEGIN IMMEDIATE` | 连接池（常驻 + 溢出 + 取连接超时）、请求级连接作用域、空闲 ping 重连 |
| 事务 | `BEGIN IMMEDIATE`；嵌套用 SAVEPOINT | `transaction()`（`BEGIN` / SAVEPOINT 嵌套），归还连接前回滚残留事务 |
| 并发写入 | 单写者，写锁串行；建议 `WORKERS=1` | 行级锁；死锁/锁等待超时单语句自动重试，显式事务整体重试 |
| 上传额度原子化 | 进程内命名互斥锁 | `GET_LOCK` 命名锁（跨进程） |
| 方言适配 | `ON CONFLICT ... DO UPDATE`、`abs(random())`、`MIN()` | `ON DUPLICATE KEY UPDATE`、`RAND()`、`LEAST()` |
| 建表与升级 | 建表 + 自动补列/补索引（兼容 1.1.x 老库） | `CREATE TABLE IF NOT EXISTS` + 结构版本记录 |
| 备份 | Online Backup API / 停服复制库文件 | `mysqldump --single-transaction` + 行数清单 |
| 健康检查 | PRAGMA 诊断（`get_db_status`） | 版本/字符集/表与索引/计数漂移/孤儿点赞（`tools/check_db.py`） |
| 数据迁移 | 后台切换 / `app/db_migration.py` | 同上；另保留 `tools/migrate_sqlite_to_mysql.py` |

功能面（前台、后台、审核、限流、封禁、日志、统计、页面/链接、敏感词、备份恢复等）在两种后端下**完全一致**，差异只在数据层实现与并发能力。

## 3. 适用场景

### SQLite（默认，推荐小站）
- 个人站、小团队、单机 / 宝塔简单部署，不想额外维护数据库
- 访问量不大、`WORKERS=1` 即可满足
- 希望备份就是复制一个文件

### MySQL（推荐高并发）
- 需要多 worker、更高并发与稳定行级锁
- 需要标准数据库运维能力（账号权限、备份、监控、主从/云数据库）
- 需要严格 utf8mb4（中文与 emoji）

### 1.1.x（仅限存量）
- 已有 SQLite 站点且暂不打算升级
- 只接受缺陷/安全补丁，不新增功能
- 新项目不建议使用，请直接使用 1.2.5（SQLite 模式与 1.1.x 数据完全兼容）

## 4. 版本号与标签规则

- 语义化版本 `MAJOR.MINOR.PATCH`：破坏性变更升 MAJOR，功能升 MINOR，修复升 PATCH。
- **1.2.x 起标签不带 `v` 前缀**（如 `1.2.0`、`1.2.5`），标签必须为注释标签并说明核心变更。
- 历史标签保留原样（`v1.1.0`、`v1.1.1`、`v1.0.x`），不再重命名或移动，避免已发布内容漂移。
- 1.1.x 后续补丁继续使用历史风格标签（`v1.1.2` 起）。

## 5. 升级路径

### 1.1.x → 1.2.5（无需迁移）

1. 停止旧服务；
2. 备份 `data/app.db`（含临时文件时请先停服）、`uploads/`、`private_uploads/`、`.env`；
3. 用 1.2.5 代码覆盖旧目录，保留数据目录与 `.env`；
4. 直接启动应用：
   - `.env` 没有 `DB_TYPE` 时按 sqlite 处理；
   - 启动时幂等补齐缺失的表/列/索引；
   - 原有图片、管理员、配置保持不变；
5. 登录后台确认数据与设置；如需改用 MySQL，进入「站点设置 → 切换数据库」。

> 1.1.x 升级**不需要**运行 `install.py`，也**不需要**执行迁移工具。

### 1.2.0 → 1.2.5

拉取 `main` → 安装依赖 → 重启服务。`.env` 保持 `DB_TYPE=mysql` 即可，启动时自动补齐结构。

### 1.2.5 内部升级

拉取 `main` → 安装依赖 → 重启服务；启动时自动幂等建表，无需手工 SQL。

### 在 SQLite 与 MySQL 之间切换

后台「站点设置 → 切换数据库」：三次确认 → 自动备份 → 复制到空目标库 → 逐表校验 → 原子更新 `.env` → 重启生效。旧库数据不会被删除。
